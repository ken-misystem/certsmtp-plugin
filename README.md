# CertSmtp 公開用候補 1.5.0-dev（未公開）

通常SMTP（STARTTLS / TLS）と、クライアント証明書＋パスワードのSTARTTLSに対応する候補です。
証明書SMTPの接続先・ポート・テスト用アドレスの店舗固有固定を解除しました。
証明書方式はメールアドレスをSMTPユーザー名と送信元に使用するサーバーが対象です。

PHP拡張の `mbstring`、`openssl`、`PDO`、`pdo_sqlite`、`sodium` が必要です。
Symfony MailerとMimeはそれぞれ `^6.4.49`（6.4.49以上7.0未満）が必要です。
EC-CUBE側がこれより古いバージョンを固定している場合、プラグイン導入前に依存関係の更新と互換性確認が必要です。
Linuxではファイルの所有者確認にPOSIX拡張も必要です。Windowsネイティブでは
POSIX所有者・権限の検査とアカウント更新の互換性を検証していません。

登録済み設定の編集・切替と、証明書/P12のアップロードに対応します。
キュー登録時のアカウント/送信元の結合、受付済み/結果不明の再送防止、最大試行回数、既存履歴を保持します。
TLSのCA・ホスト名検証を無効にせず、TLS1.2以上と接続IPの固定を維持します。
証明書SMTPは公開IPv4へ接続する構成で、private/loopback/metadata宛は許可しません。

導入だけで既存MAILER_DSNを切り替えません。SMTPアカウント、プロジェクト外の権限700/600の私有設定・キュー、
CERT_SMTP_CONFIG、certsmtp transportの採用とworkerの常駐/cronは運用側で準備が必要です。
バックアップには設定・暗号鍵・レジストリ・SQLiteキュー・試行履歴・証明書を含めます。
インストールや設定確認のために自動でテストメールを送信しません。

更新、無効化、アンインストール、復元の前にはworkerとcronなどの自動起動を停止し、
workerの終了を確認してください。更新後は管理画面と設定、キュー・鍵・試行履歴の参照先を確認してから配送を再開します。
旧店舗専用版からの直接更新は検証範囲外です。

監視で配送を制御する配備では、EC-CUBEのDIに
`Plugin\CertSmtp\Resource\Runtime\WorkerAdmission` を実装するサービスを登録し、
同じ名前のサービスIDまたはエイリアスを用意してください。workerの環境に
`CERT_SMTP_REQUIRE_WORKER_ADMISSION=1` を設定します。判定サービスは現在の配送許可を読み直し、
判定できない場合は拒否します。未接続、判定失敗、許可失効ではworkerが終了77を返します。
systemdで自動再起動を設定する場合は `RestartPreventExitStatus=77` を指定します。
監視連携を使わない構成では既定値 `0` で従来どおり動作します。

判定サービスを接続したworkerは各処理の開始時、キューからの取得前、SMTP処理の呼出し直前に許可を確認します。
取得後の拒否は接続前の中断として記録が残り、次の許可済みworkerが既存の中断復旧処理で扱います。
開始済みのSMTP処理の停止は監視側が担当します。DATA中断は配送結果不明、250応答の記録後は受付済みとして扱い、
いずれも自動・手動で再送しません。
